# 个人网站导航页 · 开发文档

> 版本：v1.0（草案）
> 日期：2026-08-11
> 状态：技术方案已确定，待开发
> 技术栈：**Vue 3 + Vite + TypeScript**（纯静态 SPA，部署公网）

---

## 1. 项目概述

### 1.1 背景与目标

日常需要访问的网站越来越多，浏览器收藏夹难以管理、无分类、无预览。本项目的目标是用 Vue 3 从零开发一个**个人专属的网站导航页**：将所有常用网站按分类组织成卡片式导航界面，支持搜索、主题切换，部署到公网后手机/任意设备均可随时访问。

### 1.2 核心定位

| 维度 | 定位 |
|---|---|
| 使用人群 | 个人（单用户） |
| 部署形态 | 纯静态 SPA，部署到公网（Vercel / Cloudflare Pages / GitHub Pages / Nginx） |
| 数据形态 | 「仓库内 JSON 数据文件」为基线 + 浏览器 localStorage 个性化覆盖 |
| 设计哲学 | 轻量、美观、零后端依赖、数据即文件（可版本管理） |

### 1.3 术语

- **分组（Group）**：导航的一级分类，如「开发工具」「影音娱乐」
- **站点（Link）**：导航的最小单位，一条网址记录
- **编辑模式**：页面上直接增删改分组/站点的模式，改动保存到 localStorage
- **基线数据**：仓库中的 `links.json`，随站点构建发布，是所有访客的默认数据

**国际项目共性结论**：

1. 纯导航页的两条主流路线：**纯静态 YAML/JSON 配置**（Homer、Flare）vs **带 UI 编辑器的 Docker 服务**（Dashy、Flame、Heimdall）。
2. 除 Dashy / Flame / Organizr / Homarr / Launchy 外，多数项目**无内置认证**，暴露公网必须套反代——对个人导航页（无敏感数据）反而不需要。
3. 无 UI 编辑器是「静态配置派」最大痛点（Homepage / Homer 改一个链接都要改 YAML）；UI 编辑器派（Dashy）则牺牲了简洁性。

**中文项目共性结论**：

1. **WebStack 系是国内导航页的审美母版**：卡片式两列/三列布局 + favicon 图标 + 分类标题，已被国内开发者普遍接受。
2. 老牌方案（WebStack-Laravel、WP 版）多已停更；当前活跃的路线是 **OneNav（PHP 后台）** 和 **Sun-Panel（Go+Docker）**。
3. 青柠起始页、iTab 等知名起始页**均未开源**，只可参考风格，不能作为实现参照。
4. 纯前端方案普遍存在「加链接要改代码」或「数据只能存浏览器」的痛点。

### 2.3 对本项目的借鉴点

| 竞品 | 借鉴什么 | 我们怎么做 |
|---|---|---|
| WebStackPage | 卡片式分类布局、favicon 图标体系 | 直接采用同款布局语言（见 §7） |
| Homer | 纯静态零后端、极简克制 | 坚持静态 SPA、无后端 |
| Dashy | 多引擎搜索 + bang 快捷方式、PWA | 做进 P1/P2 功能规划 |
| OneNav | 浏览器书签批量导入 | 做进 P1（Netscape HTML 导入） |
| Sun-Panel | 高颜值主题、小组件 | 主题系统 P0，小组件 P2 |
| Homepage / Glance | 小组件生态 | 仅做轻量「时间/天气/一言」，不做服务监控（不是本场景重点） |
| 所有「无 UI 编辑器」项目 | 它们的痛点 | **提供页面内编辑模式**（P1），这是我们的差异化点 |

### 2.4 差异化定位

> **轻量级纯静态导航页 + 页面内编辑 + 数据即文件**：
> 比 Homer/Flare 多一个「编辑模式」；比 Dashy/Heimdall 轻得多（无 Docker、无数据库、无认证）；比 WebStack 静态版多「可维护的数据文件 + 本地编辑」。

## 3. 需求分析

### 3.1 功能需求

优先级：**P0**（MVP 必须，第 1~2 周）→ **P1**（第 3~4 周）→ **P2**（持续迭代）。

#### P0 · 核心展示

| 编号 | 功能 | 说明 |
|---|---|---|
| F01 | 分类分组展示 | 分组标题 + 卡片式站点网格，支持图标、名称、描述 |
| F02 | 站内模糊搜索 | 输入关键词实时过滤匹配的站点（匹配名称/描述/URL），高亮命中 |
| F03 | 搜索引擎跳转 | 顶部搜索框默认模式：回车直接跳转所选搜索引擎 |
| F04 | 亮/暗主题 | 跟随系统 + 手动切换，localStorage 记忆 |
| F05 | 响应式布局 | 桌面多列网格；移动端单列/双列 + 触控友好 |
| F06 | 数据可维护 | 所有站点数据集中在 `links.json`，增删改走编辑模式或直接改文件 |

#### P1 · 数据管理与编辑

| 编号 | 功能 | 说明 |
|---|---|---|
| F07 | 编辑模式 | 页面内增删改分组/站点，支持拖拽排序（或上下移按钮），改动存 localStorage |
| F08 | 本地数据覆盖 | localStorage 有数据时优先于基线数据渲染（双源策略，见 §6.3） |
| F09 | JSON 导入导出 | 全量导出/导入，导出文件可回填仓库 → 重新部署即全站更新 |
| F10 | 浏览器书签导入 | 导入 Chrome/Edge/Firefox 导出的 Netscape HTML 书签 |
| F11 | 多搜索引擎切换 | Google / 百度 / Bing 等 + 用户自定义引擎 |
| F12 | 键盘快捷键 | `/` 聚焦搜索框、`Enter` 打开、`Esc` 关闭弹窗/清空搜索 |
| F13 | 站点图标兜底 | favicon 加载失败时回退为域名首字母/emoji 色块 |

#### P2 · 增强

| 编号 | 功能 | 说明 |
|---|---|---|
| F14 | PWA 离线可用 | manifest + service worker，离线打开仍可用（数据已缓存在本地后） |
| F15 | 背景壁纸 | 本地/远程壁纸，可选每日切换 |
| F16 | 轻量小组件 | 时钟 / 天气（免 key 的 wttr.in）/ 每日一言（第三方 API） |
| F17 | 自定义 CSS | 高级用户注入自定义样式 |
| F18 | 访问统计 | 可选接入 Plausible/Umami 等轻量统计 |

### 3.2 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 首屏加载 < 1s（4G）；构建产物 gzip 后 < 100KB（不含壁纸） |
| 兼容性 | Chrome / Edge / Firefox / Safari 近两年版本；移动端主流浏览器 |
| 可访问性 | 键盘可达（Tab 顺序、`/` 快捷）、主要控件带 aria-label |
| 离线 | 首次加载后，数据缓存在 localStorage，断网仍可浏览 |
| 可维护性 | TypeScript 类型覆盖数据模型；核心逻辑（合并/导入导出）有单元测试 |
| 安全 | 纯静态无后端、无 cookie、无敏感数据；第三方请求仅搜索跳转/壁纸（可选） |

### 3.3 明确不做（本期）

- ❌ 用户系统 / 多用户 / 权限（个人单用户场景）
- ❌ 服务监控、Docker 集成、媒体服务集成（Homepage/Homarr 的领地）
- ❌ 服务端存储 / 数据库（保持纯静态，公网部署零运维）
- ❌ 多语言（个人中文使用，架构上预留但不做）

## 4. 技术选型

### 4.1 选型总览

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3.5（组合式 API）+ TypeScript | 用户指定；类型安全的数据模型 |
| 构建 | Vite 6 | 秒级 HMR，产物纯静态 |
| 状态管理 | Pinia | 导航数据/设置/搜索三 store，轻量 |
| 路由 | 不引入（或仅 hash 路由） | 单页展示，无多路由需求；避免部署时 rewrite 配置 |
| 样式 | 原生 CSS + CSS 变量 + scoped | 主题切换靠变量；零依赖、体积最小 |
| 图标 | 站点 favicon + emoji + 可选 Iconify | favicon 免费真实，emoji 零成本 |
| 存储 | localStorage（封装 utils/storage.ts） | 单用户个人场景足够 |
| 测试 | Vitest（数据合并/导入导出逻辑） | 核心逻辑纯函数化，易测 |
| 代码规范 | ESLint + Prettier | 保持整洁 |

> 说明：不引入 UI 组件库（Element Plus / Naive UI）——导航页是定制化展示型页面，手写组件的体积和自由度都优于组件库。

### 4.2 数据流设计

```
┌─────────────┐     fetch      ┌──────────────────┐
│ links.json  │ ─────────────▶ │  nav store        │
│ (基线数据)   │                │  合并 localStorage │──▶ 渲染
└─────────────┘                └──────────────────┘
       ▲                              ▲
       │ 导出 JSON 回填仓库            │ 编辑模式写入
┌──────┴───────┐            ┌─────────┴────────┐
│ 重新部署上线  │            │ localStorage      │
└──────────────┘            └──────────────────┘
```

- **单向数据流**：`store` 是唯一数据源，组件只读 store 渲染。
- **本地优先**：`localStorage` 存在有效数据时覆盖基线；提供「恢复基线数据」入口（清 localStorage）。
- **更新流程**：编辑模式改本地 → 导出 JSON → 合并回仓库 → 重新部署 → 全站生效。

## 6. 数据模型设计

### 6.1 设计原则

1. **JSON 即真相**：`links.json` 与 localStorage 使用同一 schema，导出文件可直接回填仓库。
2. **版本号兜底**：schema 带 `version`，storage 封装校验版本，不匹配时丢弃旧数据。
3. **ID 稳定**：分组/站点用字符串 ID（`uuid`），拖拽排序只改 `order` 字段，不重建结构。

### 6.2 Schema

```jsonc
// public/data/links.json
{
  "version": 1,                    // schema 版本
  "updatedAt": "2026-08-11",       // 数据更新时间
  "settings": {
    "siteName": "Atlas",           // 可选：站点名（左上角 Logo + 浏览器标签标题，缺省 Atlas）
    "searchEngine": "bing",        // 当前默认引擎 id
    "searchEngines": [             // 引擎列表
      { "id": "bing", "name": "Bing", "url": "https://www.bing.com/search?q={q}" },
      { "id": "google", "name": "Google", "url": "https://www.google.com/search?q={q}" },
      { "id": "baidu", "name": "百度", "url": "https://www.baidu.com/s?wd={q}" }
    ]
  },
  "groups": [
    {
      "id": "g-dev",               // 分组 ID
      "name": "开发工具",           // 分组名
      "icon": "🛠️",               // 分组图标（emoji）
      "order": 1,                  // 排序
      "links": [
        {
          "id": "l-github",
          "name": "GitHub",
          "url": "https://github.com",
          "desc": "代码托管平台",        // 可选
          "icon": "https://github.com/favicon.ico",  // 可选：图片地址或 emoji，设置了就以它为准；缺省自动抓取站点 favicon
          "noIcon": true,               // 可选：true 时跳过图标请求（站点有 Basic 鉴权会弹登录框时使用），直接显示首字母
          "order": 1
        }
      ]
    }
  ]
}
```

### 6.3 双源数据合并规则（utils/merge.ts）

```
输入：基线数据 base（fetch 自 links.json）、本地数据 local（localStorage）
逻辑：
  1. local 不存在 / 版本不匹配 / 解析失败 → 返回 base
  2. local.version !== base.version → 返回 base（并清除 local）
  3. local 存在 → 返回 local（本地为全量快照，本地优先）
输出：合并后的完整数据
```

> 采用「全量快照 + 本地优先」而非逐项 diff 合并——个人场景下数据量小（<1MB），快照简单可靠，避免复杂的合并冲突逻辑。

### 6.4 localStorage 键名

| 键 | 内容 | 说明 |
|---|---|---|
| `nav:data:v1` | 完整导航数据快照 | 编辑模式每次操作后整体写入 |
| `nav:settings:v1` | 主题、引擎等设置 | 与数据分离，避免无关写入 |
| `nav:updatedAt` | 本地最后修改时间 | 展示/提示用 |

```
│  [页脚：版本号 / 编辑模式入口 / 数据说明]          │
└────────────────────────────────────────────────┘
```

- 桌面：内容区最大宽 1200px 居中；卡片 `grid` 自适应列数（4~6 列）。
- 移动端：卡片单列/双列（媒体查询 640px 断点）。
- 编辑模式：每个分组/卡片右上角出现「✎ / ＋ / 垃圾桶」操作按钮。

### 7.2 主题系统（variables.css）

```css
:root[data-theme="light"] {
  --bg: #f5f6fa;          --card-bg: #ffffff;
  --text: #1f2329;        --text-secondary: #6b7280;
  --accent: #4f7cff;      --border: #e5e7eb;
  --shadow: 0 2px 8px rgba(0,0,0,.06);
  --radius: 12px;
}
:root[data-theme="dark"] {
  --bg: #12141a;          --card-bg: #1c1f27;
  --text: #e5e7eb;        --text-secondary: #9ca3af;
  --accent: #6e96ff;      --border: #2a2e3a;
  --shadow: 0 2px 8px rgba(0,0,0,.4);
}
```

- 取值优先级：手动选择 > `prefers-color-scheme` > 默认亮色。
- 过渡动画：主题切换 0.2s `transition`；卡片 hover 上浮 + 描边高亮。

### 7.3 交互细节

| 交互 | 行为 |
|---|---|
| 点击卡片 | 新标签页打开 `url`（`target="_blank" rel="noopener"`） |
| 搜索框输入 | 实时站内过滤（防抖 150ms）；空结果时提示「在 Bing 中搜索 xxx」 |
| 搜索框回车 | 站内过滤无结果或输入为 URL 时跳转引擎；否则打开第一个匹配项 |
| 键盘 `/` | 聚焦搜索框（搜索框未聚焦时） |
| 站点图标 | 优先 `icon` 字段 → 自动 `https://域名/favicon.ico` → 失败回退首字母色块 |

## 9. 部署方案（公网）

### 9.1 方案对比

| 方案 | 成本 | 国内访问 | 自动部署 | 备注 |
|---|---|---|---|---|
| **Vercel**（推荐） | 免费 | 一般 | ✅ CI 集成 | 全球 CDN，绑定 GitHub 即 push 即部署 |
| Cloudflare Pages | 免费 | 较好 | ✅ | 国内访问相对稳定，有 D1 等扩展空间 |
| GitHub Pages | 免费 | 一般 | ✅ Actions | 无需任何平台账号之外的东西 |
| 自有服务器 Nginx | 有服务器则免费 | 取决于线路 | 手动 | 需要证书（certbot）与域名 |

### 9.2 推荐流程（Vercel）

```bash
npm run build          # 产物 dist/
```

1. 代码推送到 GitHub 仓库；
2. Vercel 导入仓库，框架预设选 **Vite**（构建命令 `npm run build`，输出目录 `dist`）；
3. 绑定自定义域名（可选），自动签发 HTTPS；
4. 之后每次 `git push` 自动构建部署。

### 9.3 数据更新流程（关键！）

```
本地编辑模式修改 → 「导出 JSON」 → 用导出文件替换仓库 public/data/links.json
→ git push → 自动部署 → 所有设备看到新数据
```

> 或者：直接编辑仓库中的 `links.json`（编辑模式之外的另一条路径），同样 push 即生效。

### 9.4 部署注意事项

- **无后端无认证**：页面内容公开，不要放入任何私人敏感信息（账号、token 等）。
- **SPA 单页**：不引入 history 路由，无需配置 rewrite（若以后加了多路由，Vercel 需 `vercel.json` 的 SPA fallback）。
- **CSP 与外部资源**：图标/壁纸来自第三方域时，确认 HTTPS 与 CORS；必要时配置 `meta` CSP。
- **性能**：`links.json` 与首屏 JS 走 CDN，图片图标按需加载。

## 11. 风险与注意事项

| 风险 | 说明 | 应对 |
|---|---|---|
| localStorage 数据丢失 | 清浏览器缓存/换设备即丢失 | 「导出 JSON」作为备份；换设备后导入即可 |
| 第三方 API 不稳定 | 一言/天气等免费 API 可能挂 | 组件优雅降级（加载失败隐藏），不阻塞主功能 |
| favicon 跨域/失效 | 部分站点图标抓不到 | 自动兜底：首字母色块（F13） |
| 公网可见性 | 页面无密码即可访问 | 不放敏感数据；如需保护可 P2 加前端访问口令（仅形式防护，非安全方案） |
| 青柠/iTab 等未开源 | 不可直接参照其实现 | 仅参考风格；实现参考开源项目（WebStack/Homer/Snav） |
